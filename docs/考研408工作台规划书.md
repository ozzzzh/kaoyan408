## 1. 项目概述

### 1.1 定位
**考研 408 工作台**是面向计算机考研 408 专业课(数据结构/操作系统/计算机组成原理/计算机网络)的自建备考平台,整合两个参考源:
- **408简纲**(https://simple408.cn, github.com/liangbohan/postgraduate-exam-website, **CC BY 4.0 开源**): 内容层 — 151+ 篇知识点讲解、2009–2026 共 **846 道正式真题**、44 个交互动画、408 词典搜索。
- **408os.cn**(商业产品): 体验与架构参考 — 刷题系统、四科掌握度、90 天做题贡献日历、408 通关进度、模拟考、学习计划、记忆卡片、排行榜、AI 助手等; **后端为 Java + Spring Boot(RuoYi-Vue-Plus 族)**, 其 API 风格(统一 {code,msg,data} 包 + Bearer 令牌 + 401/403 守卫)作为 408考盐 后端的设计基准(2026-10-22 实测, 见 §2.2)。

目标形态: **能学 — 能做 — 能看(数据) — 能规划 — 能比(榜单)** 的闭环备考平台。

### 1.2 目标用户
- 计算机专业 undergrad 备考 408(大一~大三);
- 跨专业/自学考生, 系统性强、数据反馈需求高;
- 后期: 考研社群成员、内容共建者。

### 1.3 核心价值
1. **题与知识双向互链**: 846 题每道关联知识点块, 题目页看知识, 知识页看题;
2. **完整知识内容**: 按大纲 147 个知识点 / 1634 个知识块讲解 + KaTeX 公式 + 交互动画 + 408 词典全文搜索;
3. **数据闭环**: 四科掌握度、90 天贡献日历、连续天数、408 通关进度;
4. **备考工具链**: 模拟考(120 分钟)、学习计划(手动/自动/弱项)、记忆卡片;
5. **长期**: 排行榜、社区讨论、内容共建。

### 1.4 明确不做(V1–V2)
- 院校选择/排名(408os 功能, 与 408 正考相关性弱);
- AI 出题(AI 解析、AI 弱点诊断为 P3 可选项, 受模型 API 成本约束);
- 移动端 App(先 Web, 响应式优先, P3)。

### 2.2 408os.cn — 体验 + 架构参考(内容不复制)
**功能模块**(登录+灰度): 首页面板、90 天贡献日历、四科掌握度(掌握/不熟/不会/未做)、模拟考、学习计划(手动/自动/弱点/社区)、记忆卡片、排行榜、AI 助手、知识图谱、算法可视化、真题大观、院校选择; 灰度标志: wd_question_bank、relax1000_question_bank、panorama_408、mock_exam、stage_summary、paper_workbench、school_selection、ai_question_tutor。
**实测架构(2026-10-22, 前端 bundle 拆解 + API 探测)**:
- **前端**: Vite + Vue 3.5 + TS + **Naive UI** + Pinia + Axios(30s timeout); 登录态 Bearer 令牌存 localStorage(`token`/`token_expire`), 请求头 `Authorization: Bearer <token>` + 自定义 `clientId` 头; 响应拦截: 401 → 全局登出+登录弹窗, 403 → 无权限提示; 全局 $message/$dialog/$notification。
- **后端**: **Java + Spring Boot (RuoYi-Vue-Plus 族)**(2026-10-22 二次探针证实): `GET https://api.408os.cn/` 返回纯文本 **"欢迎使用RuoYi-Vue-Plus后台管理框架，请通过前端地址访问。"** — 这是 RuoYi-Vue-Plus 服务默认欢迎页, 说明 API 宿主是 RuoYi-Vue-Plus 后端工程(源码未公开; 此前 v1.1 的 "NestJS" 误判来自对 404 报文的过度解读, 该报文实为 RuoYi 族全局 filter 输出)。其余特征: 统一 JSON 包 **`{code, msg, data}`**(200/401/403/404/500 均在此结构内, HTTP 恒 200); 全局 404 filter 报文 "No endpoint GET <url>."; 401 报文 "认证失败,无法访问系统资源"(RuoYi 族标准文案); 命名空间 `/api/zt/*`(真题域) + `/api/v1/*`; CORS 全开(Vary: Origin/Access-Control-*); HSTS 开; `Server: openresty`(Nginx 系反向代理)。
- **数据层**: 未公开; 按 RuoYi-Vue-Plus 族默认栈推测 **MySQL + MyBatis-Plus + Redis**。
- **数据结论**: 408os 题库 2009–2026 共 846 题, 四科 233/235/216/162 — 与 simple408 完全同源同量, 两平台题库互为镜像。

## 3. 产品设计

### 3.1 信息架构
```
考研 408 工作台
├── 工作台          /            (总览 + 快捷入口)
├── 知识点          /learn (知识树, 4 科目)
│   └── 知识详情    /learn/:subject/:point
├── 刷题            /practice
│   ├── 按年        /practice/paper/:year
│   ├── 按科目      /practice/subject/:subject
│   ├── 按知识点    /practice/block/:pointId
│   └── 自定义组卷  /practice/custom
├── 模拟考          /mock  +  /mock/report/:id
├── 统计            /stats
├── 计划            /plan
├── 搜索            /search
└── 个人中心        /me (成就/排名/卡片/反馈)
```

### 3.2 关键页面要点
- **首页**: 四科掌握度环图、90 天日历迷你版、今日进度、公告、"昨日未做题目"清单。
- **知识详情页**: 块级内容(KaTeX 公式、callout 提示框、SVG 插图、Manim 动画播放器); 右侧栏: 关联题目(已完成/未完成状态)、上一/下一知识块导航、知识树跳转。
- **刷题页**: 题干(公式渲染)、选项、答错折叠解析; 提示按钮两级(hint1 思路提示 / hint2 答案解析); 答完刷新关联知识点掌握度。(对齐 408os 刷题交互: 答错折叠解析、两级提示、即时统计)
- **模拟考**: 120 分钟倒计时、逐题跳转、断点保存、结束自动批改(选择题)出报告(正确率/用时/错题清单, 一键跳转复习)。
- **统计页**: 四科掌握矩阵(掌握/不熟/不会/未做题数)、按年正确率趋势、90 天贡献热力图、连续天数、408 通关进度(估算)。
- **计划页**: 每日计划卡(今日/弱项专项/新知识点), 完成打钩; 自动生成规则: 70% 弱项知识题 + 30% 新考点, 每日题数可配置。

## 4. 数据模型

### 4.1 内容数据(源自 simple408, 只读, 全部正式真题)
- `exam_year(id, year, title)`
- `question(id, year_id, no, subject, chapter_name, type[choice/comprehensive], score, stem, difficulty, explanation, tags JSON, image_paths JSON)`
- `question_option(id, question_id, key, text)`
- `question_subquestion(id, question_id, no, score, description)`
- `knowledge_subject / knowledge_point / knowledge_block(id, point_id, type, content, order)` — 保留 `kb-*` 原 id
- `question_knowledge(question_id, block_id)` — 关联表
- `animation(id, subject, point_id, data JSON)`
- `search_term / search_synonym`
- 索引: question(year_id, subject), tags JSON 索引, block(point_id)

### 4.2 用户与行为数据
- `user(id, username, email, password_hash, created_at)`
- `question_attempt(id, user_id, question_id, result[correct/wrong/giveup], hints_used, duration_ms, answered_at)`, 唯一(user_id, question_id)
- `answer_history(id, attempt_id, ...)` — 全量答题流水(趋势用)
- `block_progress(user_id, block_id, status, total, done, correct_ratio)`
- `daily_stat(user_id, date, questions, correct, minutes, streak)` — 聚合
- `mock_session(id, user_id, year_id, started_at, duration, score)` + `mock_answer(user_id, mock_id, question_id, result, duration_ms)`
- `plan(id, user_id, kind, gen_rules JSON, tasks JSON)` + `plan_task(id, plan_id, day, block_id, question_ids JSON, done_at)`
- `memory_card(id, user_id, content JSON, reviews JSON)`
- `feedback(id, user_id, type, content)`

### 4.3 关键指标算法
- **掌握度(块级)**: 关联题 >=3 且正确率 >=80% -> 掌握; 正确率 <40% -> 不会; 其余 -> 不熟; 无记录 -> 未做。科掌握率按该科题数加权。
- **408 通关进度**: 四科掌握率按各科分值权重(各 1/4)加权合成, 0–100%; 标注"估算值"。
- **已做题数/总题目**: 有 attempt 的 distinct 题数 / 846。
- **连续天数**: 由 daily_stat 推算(当日 >=1 题算连续)。

### 4.4 模拟卷构成(默认提案)
默认 = 单个年份整卷(47 题, 120 分钟); P1 起支持组卷器(按科目/章节/难度抽题)。综合题: P1 仅记录作答, 评分留给人工/AI(V3)。

## 5. 技术架构

### 5.1 总体(对齐 408os 实测架构, 2026-10-22 核验)
```
浏览器 (Vite + Vue3 + TS + 知识组件 KaTeX/Manim + 刷题 UI)
   | HTTPS
Nginx/openresty (静态资源 + /api 反向代理, HSTS)
   |
API 服务 **Java + Spring Boot (RuoYi-Vue-Plus 族)** (Controller/Service/Mapper + Spring Security + 全局异常处理; 统一 {code,msg,data} 包; Bearer 令牌 + clientId 头)
   |
MySQL 8 (内容+用户数据)      Redis (会话缓存/限流/榜单)
```
与 408os 同族: Spring Boot 后端 + openresty 反代 + Bearer 令牌 + JSON 包 + 401/403 守卫 — 但数据层独立, 内容取自 simple408, 不碰 408os 任何数据/代码。

### 5.2 前端
- **沿用 simple408 技术栈与知识组件**(迁移成本最低): Vite + Vue 3.5 + TS + Tailwind 4 + Vue Router; 知识内容部分直接用 408简纲的 BlockRenderer/KaTeX/Manim/搜索组件。
- 刷题/统计/计划页 UI 按 408os 交互参考(答题折叠解析、两级提示、掌握度环、贡献日历), 视觉用 Tailwind 自研, 不抄 408os 样式资产。
- 图表 echarts; 状态管理 Pinia(对齐 408os 前端习惯, 便于将来组件互借鉴)。
- **UI 库: Tailwind 已确定(用户 2026-10-22 确认)**: 实测 408os /dashboard 前端为 Vite + Vue 3.5 + **Naive UI** + Pinia(构建产物含独立 `naiveui-ZrXIyLCB-…js` 组件包 + 每页独立 `.css`, 非 Tailwind)。本平台选 Tailwind(延续 simple408 资产, 迁移成本最低, 视觉语言自研); 若后续想要更贴近 408os 的观感, 再评估换/引入 Naive UI, 当前不动。
- 内容构建: 复用 simple408 的"TS 内容 -> JSON"构建期流程, 构建时校验(等价 validate:content), 防结构破坏。
- 响应式优先(桌面/平板/手机自适应), 不做独立 App。

### 5.3 后端(Spring Boot, 对齐 408os API 风格)
- 框架: **Java 17 + Spring Boot 3.4 + Spring Security + MyBatis-Plus + Jakarta Validation**, 按 RuoYi-Vue-Plus 族组织(其标准响应即 {code,msg,data} 包); 全局 `@RestControllerAdvice` 把异常统一包成 **`{code, msg, data}`**(HTTP 恒 200; 404 统一报文 "No endpoint GET <url>.", 对齐 408os); DTO 用 Jakarta Validation。
  - **Java 版本说明(v1.3 修订)**: 规划书原写 Java 21, 但本机环境为 **OpenJDK 17.0.19**(IDEA 内置运行时 `D:\jdk`), Spring Boot 3.4 的基线即 Java 17, 故定为 17。若后续要用虚拟线程等 21 特性再整体升级, 届时同步改 Docker 基础镜像。
  - 落地坐标: `mybatis-plus-spring-boot3-starter:3.5.17`、`flyway-core` + `flyway-mysql`、`jjwt:0.12.6`、Lombok。
  - **数据库迁移用 Flyway**: `V1__init.sql`(表结构) + `V2__seed_content.sql`(内容种子, 由 `scripts/import-content.mjs` 生成, 约 2.96 MB)。容器首发即自动建表灌数据, 无需手工导入。
- 模块划分: `auth`(登录/令牌) / `exam`(卷+题) / `knowledge`(知识树+块+动画) / `attempt`(答题) / `stat`(统计聚合) / `mock`(模拟考) / `plan`(计划) / `feedback` / `rank`(榜单, P2) / `flag`(功能灰度, 可选)。
- 认证/守卫: Spring Security + JWT(Bearer 令牌存 localStorage, 对齐 408os 惯例; 401 返回统一包, 前端全局登录弹窗); 密码 BCrypt; 可选 FeatureGuard(对齐 408os 灰度机制: `requiredFeature` 配置化, 如 `mock_exam`、`memory_cards`)。
- 请求头约定: `Authorization: Bearer <token>` + `clientId: 408kaoyan`(对齐 408os 的 clientId 头惯例, 便于日志区分客户端)。
- API 命名: 统一 `/api/v1/*` 前缀(408os 的 `/api/zt/*` 是域前缀风格, 本平台用版本前缀, 更常规; 2 种风格择一, 默认 `/api/v1/`)。
- **接口清单(节选)**:
  | Method | Path | 说明 |
  |---|---|---|
  | POST | /api/v1/auth/login | 登录, 返回 Bearer 令牌 + 到期时间 |
  | GET  | /api/v1/user/current | 当前用户(对齐 408os 同名端点) |
  | GET  | /api/v1/exams | 年份列表 |
  | GET  | /api/v1/exams/:year | 整卷(题+选项) |
  | GET  | /api/v1/questions/:id | 单题详情(未答时不含解析) |
  | POST | /api/v1/questions/:id/answer | 提交答案, 返回统计快照 |
  | GET  | /api/v1/stats/dash | 主页统计(掌握度/日历/进度) |
  | GET  | /api/v1/knowledge | 知识树 |
  | GET  | /api/v1/knowledge/block/:id | 块内容 + 关联题目及完成状态 |
  | POST | /api/v1/mock/start /mock/:id/submit /mock/:id/report | 模拟考闭环 |
  | POST | /api/v1/plans/auto /plan/:id | 计划生成与查询 |
  | GET  | /api/v1/search?q=&scope= | 题+知识检索 |
  | POST | /api/v1/feedback | 意见反馈 |
- 安全: JWT(Bearer, 存 localStorage — 对齐 408os 惯例, 简单一致; 后续可升级 httpOnly cookie); 答题接口限流(每用户每分钟 <=6 次, Redis 计数)+ IP 级限流(Redis); 防解析泄露: 未作答时后端不下发解析, 前端不缓存。
- 错误模型: 401(未登录, 触发前端全局登录弹窗)/403(无权限, 功能灰度未开)/400(校验失败)/404(全局 filter, "No endpoint GET <url>.")/500(系统异常) — 统一进 `{code, msg, data}` 包。
- 数据: MySQL 8 + MyBatis-Plus(实体/Mapper 按 §4 模型, 建表 + Flyway 版本号化); Redis(缓存/限流/榜单 ZSET)。

### 5.4 部署
